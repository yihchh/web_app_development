# PRD - 任務管理系統

## 1. 專案概述
- **背景與動機**：現代人處理日常瑣事繁多，容易遺漏重要任務。本系統旨在提供一個輕量、簡單易用的任務管理工具，幫助個人提升生活與工作效率。
- **目標用戶**：需要管理日常工作的個人用戶。
- **核心價值主張**：提供最直覺的新增、刪除與狀態追蹤功能，讓日常任務管理沒有任何負擔，隨時掌握進度。

## 2. 功能需求

### 系統主要功能
1. 新增任務：使用者可快速建立任務事項。
2. 標註任務狀態：可將任務標註為完成或未完成狀態（根據輸入的「標註新增任務」推測）。
3. 刪除任務：移除不需要或已作廢的任務。
4. 顯示所有任務清單：一目了然看見所有目前紀錄的任務。
5. 依完成狀態篩選：根據「已完成」、「未完成」過濾清單顯示。

### 使用者故事 (User Stories)
- **作為**一名個人用戶，**我希望**能夠快速輸入任務名稱並新增，**以便**記錄需要完成的工作。
- **作為**一名個人用戶，**我希望**能夠點選狀態將任務標註為完成，**以便**追蹤實際的工作進度。
- **作為**一名個人用戶，**我希望**能夠刪除不需要或建立錯誤的任務，**以便**保持清單內容的整潔與明確性。
- **作為**一名個人用戶，**我希望**能一眼看出目前所有任務的列表，**以便**快速檢視今日的總覽與待辦數量。
- **作為**一名個人用戶，**我希望**能利用篩選器切換查看「已完成」或「未完成」的任務，**以便**讓我專注在當下尚未解決的事情上。

## 3. 非功能需求
- **技術限制**：採用輕量化架構，以 Python 的 Flask 作為後端框架，搭配 Jinja2 樣板引擎處理畫面渲染，並使用 SQLite 做為資料庫，易於開發與部署。
- **效能考量**：操作需維持在輕巧流暢的標準，頁面重新整理或 AJAX 操作反應時間應短暫無延遲。
- **安全考量**：確保表單資料傳遞之安全性，防止基礎的 SQL Injection 及 XSS 等常見網頁弱點攻擊。

## 4. MVP 範圍 (Minimum Viable Product)

| 功能項目 | 優先級別 | 說明 |
| -------- | -------- | ---- |
| 新增任務 | Must Have | 系統最基本的核心功能 |
| 顯示所有清單 | Must Have | 提供使用者檢視清單資料的能力 |
| 標註任務狀態 | Must Have | 滿足基礎狀態追蹤的核心管理需求 |
| 刪除任務 | Should Have | 提供使用者維護清單的完整度，避免無效資料堆積 |
| 依完成狀態篩選 | Nice to Have | 提升在大量任務發生時的視覺尋找效率 |
